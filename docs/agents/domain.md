# Domain docs

This repository uses a single context.

## Before exploring

- Read `CONTEXT.md` at the repository root: it is the glossary. Wherever an
  engineering skill says `GLOSSARY.md`, read `CONTEXT.md` instead.
- Read ADRs in `docs/adr/` that touch the area you are working in.

If a document does not exist, proceed silently. Create ADRs only when a
resolved decision needs one, not as scaffolding.

## Vocabulary and decisions

Use the terms defined in `CONTEXT.md` in code, tests, issues and proposals.
If a needed term is missing, note the gap for `/domain-modeling` rather than
inventing a synonym. Surface any conflict with an existing ADR explicitly.
